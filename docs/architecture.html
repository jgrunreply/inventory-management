Request Data Flow

1

User Interacts with FilterBar

User selects Period, Location, Category, or Order Status from the sticky FilterBar.vue dropdown. Each selection updates a reactive ref() inside the useFilters composable — a singleton shared across all views.

2

View Watcher Triggers

Each view sets up a watch([selectedLocation, selectedCategory, ...], loadData). The watcher fires immediately on filter change and calls the view's data-loading function.

3

API Call via api.js

The view calls getCurrentFilters() to get { warehouse, category, status, month }, then passes them to a method in api.js (e.g., getOrders(filters)). Axios builds a GET request with URLSearchParams, e.g., GET /api/orders?warehouse=Tokyo&status=Shipped.

4

FastAPI Receives & Filters

The FastAPI route in main.py accepts query params, passes them to apply_filters(items, warehouse, category, status) which iterates the in-memory list. Month filtering uses filter_by_month(), which supports both exact months (2025-01) and quarters (Q1-2025). Values of "all" are skipped.

5

Pydantic Validation + JSON Response

Filtered results are validated against Pydantic models (e.g., List[Order]) and serialized to JSON. FastAPI returns the response to the frontend.

6

Vue Reactive Update

The view stores raw API data in a ref() (e.g., allOrders.value = response). Derived data is computed via computed() — search queries, sort orders, or cross-referencing (e.g., backlog matching filtered inventory). Vue re-renders the template automatically.

Key Patterns

Singleton Composable State

Filter state lives in useFilters.js as module-level ref()s. All views import the same instance — changing a filter in FilterBar automatically propagates to every active view without prop drilling or an event bus.

Raw ref + derived computed

API data is stored in raw ref()s (allOrders, inventoryItems). Display-ready data — sorted, searched, or cross-referenced — lives in computed() properties. This ensures the original API response is never mutated.

Loading / Error / Data pattern

Every view uses a consistent trio: loading = ref(true), error = ref(null), data = ref([]). A try/catch/finally block in the load function sets each appropriately, and the template renders conditionally.

Client-side search on server-filtered data

Warehouse/category/status/month filters are applied server-side. Free-text search (e.g., item name) is applied client-side via a computed() filter on the already-filtered API response — no extra round-trips.

Modal state management

Each view manages modals with a showModal = ref(false) + selectedItem = ref(null) pair. Clicking a row sets both, the modal reads selectedItem via props, and emits @close to hide itself.

In-memory filtering (backend)

apply_filters(items, warehouse, category, status) iterates the full in-memory list on every request. Values of "all" skip that filter. Month queries are parsed in filter_by_month(), which maps quarter strings (e.g., Q1-2025) to month ranges.
